GoStick

CSGOSKINS Sticker Scraper

Automated web scraping, background removal, and cloud asset management

Project Overview

GoStick is an intelligent web scraper for CSGOSKINS.GG that automates the process of discovering, downloading, and processing CS:GO stickers with HD quality. The system removes backgrounds, manages metadata, and integrates with Cloudinary for asset delivery.

Key Features

  • Smart Pagination: Scrape 233 pages of sticker listings with configurable rate limiting
  • HD Screenshot Capture: Download inspection images at maximum quality from detail pages
  • Background Removal: Automated blue background removal using image processing
  • Cloudflare Handling: Bypass Cloudflare protection using verified Chrome sessions
  • Asynchronous Pipeline: Queue-based processing with up to 8 concurrent operations
  • Persistent Metadata: JSON manifest tracks URLs, categories, processing status, and Cloudinary references
  • Cloudinary Integration: Direct upload with stable public IDs and delivery URL tracking
  • Resumable Sessions: Chrome profile persistence allows graceful resume on interruption

Technical Stack

  • Language: Python with async/await
  • Browser Automation: Playwright with Chrome DevTools Protocol (CDP)
  • Image Processing: Background removal in worker threads
  • Cloud Storage: Cloudinary API integration
  • Rate Limiting: Configurable request throttling (6-10 requests/minute)

Smart Features

Cloudflare Bypass

Uses a verified Chrome window with persistent profile to pass security checks, avoiding repeated verification loops.

Adaptive Rate Limiting

Respects site rate limits while providing jittered delays and extended cooldowns after security challenges (up to 3 minutes).

Streaming Processing

Downloads and processes images in the background while the scraper continues navigating, using a bounded queue to prevent memory overrun.

Atomic Updates

Manifest is updated atomically after each sticker completes, ensuring data integrity across interruptions.

Architecture Highlights

The system uses a producer-consumer pattern where the scraper continuously produces sticker URLs while a processing coroutine consumes them, downloading, transforming, and uploading in parallel. The pipeline buffer caps memory at ~8 items, automatically throttling discovery if processing falls behind.

Configuration Options

--start-page / --end-page Range of sticker pages to process
--output Output directory for stickers and manifest
--cdp-url Chrome DevTools Protocol endpoint (localhost:9222)
--requests-per-minute Rate limit (default: 10, recommended: 6)
--request-jitter Random delay variance in seconds (default: 1.5)
--challenge-cooldown Wait time after Cloudflare check (default: 120)
--pipeline-buffer Max concurrent downloads (default: 8)
--upload-cloudinary Upload directly during scraping
--cloudinary-folder Organization path in Cloudinary

Setup & Execution

# Initialize Python environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m playwright install chromium

# Start verified Chrome session (complete Cloudflare check manually)
.\open_verified_chrome.ps1

# Single page test
python scrape_stickers.py --start-page 233 --end-page 233 --output output --cdp-url http://127.0.0.1:9222

# Full scrape with conservative rate limiting
python scrape_stickers.py --start-page 1 --end-page 233 --output output \
  --cdp-url http://127.0.0.1:9222 \
  --requests-per-minute 6 \
  --request-jitter 2 \
  --challenge-cooldown 180

# Upload existing stickers to Cloudinary
python scrape_stickers.py --output output --upload-existing \
  --cloudinary-folder gostick.gg/stickers

Status & Output

The scraper generates output/stickers.json containing full metadata for each processed item: inspection URLs, category references, transparent PNG paths, Cloudinary delivery URLs, image dimensions, and processing timestamps.

Security Notes

  • Cloudinary credentials are stored locally in .env (excluded from git)
  • Chrome profile is retained for cookie reuse across sessions
  • Never commit secrets; always use environment variables
  • Rate limiting is intentionally conservative to avoid verification loops
